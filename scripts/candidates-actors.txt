# Per-ACTOR candidate feeds -- UNMEASURED until probed.
#
#   bash scripts/probe_feeds.sh scripts/candidates-actors.txt
#
# WHY THIS FILE EXISTS
#
# build_source_plan() already tailors sources per market: it takes the rule's
# parties/mediators, adds their official domains from ACTORS, the wire domains,
# the market's named resolution source, and Google News queries built from the
# decisive-event vocabulary. Per-market tailoring is therefore already
# automatic and rule-derived -- hand-writing one source list per market would
# duplicate it and go stale the moment markets resolve and new ones list.
#
# The starvation point is DIRECT_ACTOR_FEEDS. ACTORS defines 31 actors with
# official domains, but DIRECT_ACTOR_FEEDS has feeds for exactly ONE of them
# (united_states). So direct_feeds() returns nothing for a market about Iran,
# Israel, Qatar, Russia or China, and every such market falls back to the same
# 9 GENERAL_FAST_FEEDS plus aggregator queries -- identical sources regardless
# of who the market is actually about.
#
# Filling this table tailors EVERY market involving these actors at once,
# including markets that list next month. That is the leveraged fix; a
# hand-built top-50 list is not.
#
# Official feeds are CONFIRMATION, not speed: the ones already wired measured
# 2.7-5.6 DAYS stale, so build_source_plan deliberately orders them after the
# credible-reporting feeds. Wire the survivors here as official/poll sources,
# never as the leading trigger.
#
# Format: actor key, then its candidate feed URLs. Keys match ACTORS in
# polybot/discovery/registry.py so survivors drop straight into
# DIRECT_ACTOR_FEEDS.
